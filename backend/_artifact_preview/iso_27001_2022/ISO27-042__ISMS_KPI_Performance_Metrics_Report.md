### Column Guidance

| Column | What to enter |
|---|---|
| Reporting Period | Enter the period covered by the measurement in YYYY-MM format for monthly reporting, YYYY-Q# for quarterly reporting, or YYYY for annual reporting. |
| KPI ID | Enter a unique identifier for the metric, e.g. KPI-ISMS-001. Keep this ID stable across reporting periods. |
| KPI Name | Enter a short, descriptive name for the KPI, e.g. Security Incident Closure Time or Access Review Completion Rate. |
| ISMS Objective / Requirement Monitored | Identify the ISMS objective, risk treatment objective, process, policy commitment, or compliance requirement being monitored by this KPI. |
| ISO/IEC 27001:2022 Reference | Enter the relevant clause or Annex A control reference, e.g. Cl. 6.2, Cl. 8.1, Cl. 9.1, A.5.24, A.8.15. Use N/A only where the KPI supports a local ISMS objective without a direct control reference. |
| Metric Definition | Define exactly what is being measured, including numerator and denominator where applicable, so the KPI can be reproduced consistently. |
| Measurement Method | Describe how the result is calculated or assessed, including formula, sampling approach, query, report name, or manual review method. |
| Data Source / Evidence Location | Enter the authoritative source system, report, register, ticket queue, dashboard, or document repository path used to obtain the KPI result. |
| Measurement Frequency | Enter how often the KPI is measured. Allowed values: Daily, Weekly, Monthly, Quarterly, Semi-Annual, Annual, Event-Driven. |
| KPI Owner | Enter the role or named accountable person responsible for producing and explaining the KPI result, e.g. Security Operations Manager. |
| Target / Acceptance Criteria | Enter the required performance level or pass criteria, including unit and comparison operator, e.g. >= 95%, <= 5 business days, 0 critical overdue actions. |
| RAG Thresholds | Define Red/Amber/Green thresholds for this KPI in measurable terms, e.g. Green >=95%, Amber 90-94.9%, Red <90%. |
| Unit of Measure | Enter the unit used for the result, e.g. %, count, days, hours, score, Yes/No. |
| Current Period Result | Enter the measured value for the reporting period using the stated unit of measure. Do not enter analysis here. |
| Previous Period Result | Enter the result from the immediately preceding reporting period using the same unit of measure, or N/A if this is the first measurement. |
| Trend | Enter the direction of movement compared with the previous period. Allowed values: Improving, Stable, Deteriorating, New KPI, N/A. |
| RAG Status | Enter the status based on the defined RAG thresholds. Allowed values: Red, Amber, Green, N/A. |
| Analysis / Interpretation | Explain what the result means, including key causes, notable changes, recurring weaknesses, scope limitations, or data quality issues. |
| Effectiveness Conclusion | State whether the monitored ISMS activity or control is effective based on the result. Allowed values: Effective, Partially Effective, Ineffective, Not Yet Measured. |
| Nonconformity / Issue Reference | Enter the linked nonconformity, risk, audit finding, incident, or issue ID if the KPI result requires formal tracking; otherwise enter N/A. |
| Corrective Action / Improvement Action | Describe the action required where the KPI is Red, Amber, deteriorating, or otherwise indicates improvement is needed. Enter N/A if no action is required. |
| Action Owner | Enter the role or named person accountable for completing the corrective or improvement action. Enter N/A if no action is required. |
| Action Due Date | Enter the due date for the action in YYYY-MM-DD format. Enter N/A if no action is required. |
| Management Review Input Required | Indicate whether the KPI result must be escalated or included in ISMS management review. Allowed values: Yes, No. |
| Approved By | Enter the role or name of the person who reviewed and approved the KPI report for the reporting period. |
| Approval Date | Enter the date the KPI report was approved in YYYY-MM-DD format. |

### Maintenance

The Information Security Manager owns this template and updates it at least monthly or quarterly in line with the ISMS measurement plan, with formal review during management review. Results should be drawn from authoritative source systems such as GRC tools, SIEM/SOC dashboards, ITSM records, IAM platforms, vulnerability scanners, audit logs, risk registers, and corrective action trackers.
