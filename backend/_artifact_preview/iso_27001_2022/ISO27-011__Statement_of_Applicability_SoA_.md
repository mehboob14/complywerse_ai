### Column Guidance

| Column | What to enter |
|---|---|
| SoA Version | Enter the controlled version of this Statement of Applicability entry, using format vX.Y, e.g. v1.0. |
| SoA Review Date | Enter the date this control applicability decision was last reviewed, in YYYY-MM-DD format. |
| Annex A Control ID | Enter the ISO/IEC 27001:2022 Annex A control reference exactly, e.g. 5.1, 6.3, 8.12. Each of the 93 Annex A controls should have one row. |
| Annex A Control Title | Enter the official Annex A control title for the control ID, e.g. Information security policies, Information security awareness, Data leakage prevention. |
| Annex A Theme | Enter the Annex A theme using one allowed value: Organizational, People, Physical, Technological. |
| Control Applicability | Select whether the control is applicable to the organisation. Allowed values: Applicable, Not Applicable. |
| Applicability Justification | Enter a concise rationale explaining why the control is applicable or not applicable, based on risk assessment, business context, legal/regulatory/contractual obligations, interested-party requirements, and the scope of the ISMS. |
| Reason for Inclusion | If Control Applicability is Applicable, state why the control is included in the ISMS, such as risk treatment need, legal requirement, contractual requirement, business requirement, or baseline security requirement. Enter N/A if not applicable. |
| Reason for Exclusion | If Control Applicability is Not Applicable, state the specific justification for exclusion and why exclusion does not create unacceptable information security risk. Enter N/A if applicable. |
| Risk Treatment Link | Enter the linked risk treatment plan item, risk ID, or treatment decision reference that selected or rejected this control, e.g. RTP-001 or RISK-014/TREAT-02. Enter N/A only where the control is included solely due to legal, contractual, or baseline requirements. |
| Requirement Source | Identify the source driving the applicability decision. Allowed values: Risk Assessment, Legal/Regulatory, Contractual, Business Requirement, ISO 27001 Baseline, Customer Requirement, Other. |
| Implementation Status | Record whether the applicable control is implemented. Allowed values: Implemented, Partially Implemented, Planned, Not Implemented, Not Applicable. |
| Implementation Description | Describe how the control is or will be implemented in the organisation, including key processes, tools, procedures, or responsible functions. For excluded controls, enter N/A. |
| Control Owner | Enter the accountable role or function responsible for operating or implementing the control, not an individual’s informal name unless this is the organisation’s naming convention. |
| Evidence Reference | Enter references or links to evidence demonstrating implementation or planned implementation, such as policy IDs, procedure IDs, ticket IDs, system reports, screenshots, audit records, or repository links. Enter TBD if not yet available. |
| Implementation Target Date | For controls not fully implemented, enter the planned completion date in YYYY-MM-DD format. Enter N/A if Implemented or Not Applicable. |
| Residual Risk Reference | Enter the residual risk ID or acceptance reference associated with the control decision, especially where the control is partially implemented, planned, not implemented, or excluded. Enter N/A if not applicable. |
| Management Approval Status | Record approval state of the applicability and implementation decision. Allowed values: Draft, Under Review, Approved, Rejected. |
| Comments | Enter any additional audit-relevant notes, assumptions, dependencies, or pending decisions. Enter N/A if none. |

### Maintenance

The Statement of Applicability template is owned by the ISMS Manager or Information Security Manager and approved by ISMS top management. It is updated after each risk assessment or risk treatment change, after legal/contractual/scope changes, and at least annually, drawing from the risk register, risk treatment plan, control evidence repository, legal/contractual obligations register, supplier assurance records, and ISMS document control system.
