### Column Guidance

| Column | What to enter |
|---|---|
| Programme ID | Enter the unique identifier for the multi-year internal audit programme, e.g. IAP-2025-2027. |
| Programme Period | Enter the full date range covered by the audit programme in format YYYY-MM-DD to YYYY-MM-DD. |
| Audit Year | Enter the calendar or financial year in which the audit is planned, format YYYY. |
| Audit Cycle | Enter the audit cycle within the programme, e.g. Year 1, Year 2, Year 3, H1, H2, Q1, Q2, Q3, or Q4. |
| Audit ID | Enter a unique identifier for the individual planned audit, e.g. IA-2025-001. |
| Audit Title | Enter a concise title describing the audit, e.g. Access Control Audit or ISMS Governance Audit. |
| Audit Type | Select the type of internal audit: ISMS Clause Audit, Annex A Control Audit, Process Audit, Site Audit, Supplier-Related Audit, Thematic Audit, Follow-up Audit, or Integrated Audit. |
| ISMS Scope Area | Enter the part of the certified or intended ISMS scope covered by the audit, aligned to the organisation’s ISMS scope statement. |
| Business Unit / Function | Enter the department, team, service, or organisational function responsible for the area being audited. |
| Location / Site | Enter the physical site, country, region, data centre, cloud environment, or Remote if applicable. |
| Process / Activity to be Audited | Enter the specific process, service, system, or activity subject to audit, e.g. risk assessment, incident management, supplier management, HR onboarding. |
| ISO/IEC 27001:2022 Clauses Covered | Enter applicable ISO/IEC 27001:2022 clause references, e.g. 4.1, 5.3, 6.1.2, 8.1, 9.2, 10.2; use N/A if only Annex A controls are covered. |
| Annex A Controls Covered | Enter applicable Annex A control references, e.g. A.5.15, A.5.23, A.8.15; use N/A if not applicable. |
| Audit Criteria | Enter the requirements against which conformity will be assessed, such as ISO/IEC 27001:2022, Statement of Applicability, internal policies, procedures, legal/regulatory requirements, contracts, and risk treatment plans. |
| Audit Scope Statement | Enter clear boundaries for the audit, including what is included and any exclusions, so the audit extent is unambiguous. |
| Audit Objective | Enter the purpose of the audit, e.g. to verify conformity, implementation effectiveness, control operation, readiness for certification, or closure of previous findings. |
| Audit Frequency | Enter the planned recurrence for this audit area, e.g. Annual, Six-monthly, Quarterly, Biennial, Triennial, Event-driven, or One-off. |
| Planned Start Date | Enter the planned audit start date in format YYYY-MM-DD. |
| Planned End Date | Enter the planned audit end date in format YYYY-MM-DD. |
| Planned Duration | Enter the expected audit effort in days or hours, e.g. 2 days or 6 hours. |
| Priority / Criticality | Select High, Medium, or Low based on the importance of the process, information security risk, regulatory exposure, change impact, and previous audit results. |
| Rationale for Scheduling | Enter why this audit is planned at this time, explicitly referencing importance of the process, changes affecting the organisation, risk level, previous audit results, compliance obligations, or management request. |
| Inputs Considered | List the planning inputs used, such as risk assessment, Statement of Applicability, previous audit reports, nonconformities, incidents, changes, management review outputs, supplier performance, or regulatory obligations. |
| Previous Audit Result Reference | Enter the reference to any previous audit report, finding, or conclusion that influenced this schedule; enter N/A if no previous result exists. |
| Significant Changes Considered | Enter relevant organisational, technical, legal, supplier, process, personnel, system, or threat changes considered when planning this audit; enter None if no significant change applies. |
| Lead Auditor | Enter the named lead auditor or role responsible for conducting the audit; must not audit their own work. |
| Audit Team | Enter names or roles of additional auditors or technical specialists; enter N/A if there are none. |
| Auditor Independence Confirmed | Select Yes, No, or Pending to confirm auditors are objective and impartial and are not auditing their own area of responsibility. |
| Auditee Owner | Enter the process owner, control owner, or manager responsible for the audited area. |
| Management Sponsor | Enter the senior manager accountable for ensuring audit access, cooperation, and escalation where required. |
| Audit Method | Select On-site, Remote, Hybrid, Document Review, Interview, Observation, Sampling, Technical Evidence Review, or a combination. |
| Evidence Sources Planned | Enter the expected evidence sources, such as policies, procedures, tickets, logs, system configurations, access reviews, risk records, training records, supplier records, meeting minutes, or interviews. |
| Reporting Due Date | Enter the planned date by which the audit report must be issued to relevant management, format YYYY-MM-DD. |
| Report Recipients | Enter the roles or governance bodies that will receive the audit report, e.g. ISMS Manager, CISO, Risk Committee, Process Owner, Top Management. |
| Follow-up Audit Required | Select Yes, No, or To be determined to indicate whether a follow-up audit is planned or may be required for nonconformities or significant findings. |
| Follow-up Planned Date | Enter the planned follow-up date in format YYYY-MM-DD, or N/A if not applicable. |
| Programme Status | Select Planned, Approved, Scheduled, In Progress, Completed, Deferred, Cancelled, or Rescheduled. |
| Approval Status | Select Draft, Submitted for Approval, Approved, Rejected, or Superseded. |
| Approved By | Enter the name and role of the authorised approver for the audit programme or schedule entry. |
| Approval Date | Enter the approval date in format YYYY-MM-DD, or leave blank until approved. |
| Change Log / Notes | Enter any changes to the planned audit, reason for change, date of change, and author of change; use this to preserve planning history. |

### Maintenance

The ISMS Manager or Internal Audit Programme Owner owns this template and updates it at least annually, and whenever significant organisational, technical, risk, supplier, legal, or audit-result changes occur. It draws from the ISMS scope statement, risk assessment, Statement of Applicability, previous internal audit reports, nonconformity/corrective action records, change register, incident records, supplier register, and management review outputs.
