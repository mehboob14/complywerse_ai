### Column Guidance

| Column | What to enter |
|---|---|
| Roadmap Item ID | Enter a unique identifier for the roadmap item, using a consistent format such as ISMS-RM-001. |
| Phase | Enter the implementation phase this item belongs to; allowed values: Initiation, Context & Scope, Risk Assessment, Risk Treatment, Policy & Governance, Control Implementation, Awareness & Competence, Monitoring & Internal Audit, Management Review, Certification Readiness, Continual Improvement. |
| ISO 27001:2022 Clause/Annex A Reference | Enter the relevant ISO/IEC 27001:2022 clause or Annex A control reference, such as 4.3, 5.2, 6.1.2, 6.1.3, 6.2, 7.2, 9.2, A.5.1; use N/A only where no direct reference applies. |
| ISMS Objective Supported | Enter the specific information security objective supported by this item, aligned to ISO 27001; the objective should be measurable and relevant to the ISMS. |
| Roadmap Activity / Deliverable | Describe the planned activity or deliverable to be completed, using action-oriented wording such as 'Define ISMS scope statement' or 'Complete internal audit programme'. |
| Scope / Boundary | Enter the organisational area, location, system, process, business unit, or ISMS scope element affected by this roadmap item. |
| Success Criteria / Measurable Target | Enter the measurable result that will demonstrate completion, including target metric, threshold, or acceptance criteria where applicable. |
| Planned Start Date | Enter the planned start date in YYYY-MM-DD format. |
| Planned Completion Date | Enter the planned completion date in YYYY-MM-DD format. |
| Milestone Date | Enter the key milestone date in YYYY-MM-DD format; if the activity has no separate milestone, repeat the planned completion date. |
| Milestone Description | Describe the milestone to be achieved by the milestone date, such as 'Draft policy approved' or 'Risk treatment plan baselined'. |
| Owner | Enter the single accountable role or named person responsible for delivery, such as ISMS Manager, Risk Owner, IT Operations Manager, or HR Manager. |
| Supporting Roles | Enter the roles or teams supporting delivery, separated by semicolons; use N/A if none. |
| Required Resources | Record the people, budget, tools, systems, external support, or time required to complete the item. |
| Dependencies | Enter prerequisite roadmap item IDs, decisions, systems, suppliers, or approvals required before this item can be completed; use None if there are no dependencies. |
| Priority | Enter the delivery priority; allowed values: Critical, High, Medium, Low. |
| Status | Enter the current implementation status; allowed values: Not Started, Planned, In Progress, Blocked, Complete, Deferred, Cancelled. |
| RAG Rating | Enter the current delivery health; allowed values: Red, Amber, Green, Not Assessed. |
| Progress % | Enter the estimated completion percentage as a whole number from 0 to 100. |
| Evidence / Output Location | Enter the repository path, system link, document reference, or ticket reference where evidence or deliverables will be stored; use TBD until available. |
| Effectiveness Evaluation Method | Describe how the organisation will evaluate whether the completed item achieved the intended objective, such as KPI review, audit test, control testing, management review, incident trend analysis, or training completion report. |
| Evaluation Due Date | Enter the date the result or effectiveness will be evaluated in YYYY-MM-DD format. |
| Risks / Issues | Record known risks, blockers, constraints, or issues affecting delivery; include issue or risk register reference where available, or enter None. |
| Management Review Required | Enter Yes or No to indicate whether the item or its results must be reviewed by top management or the ISMS governance forum. |
| Approval Status | Enter the current approval state; allowed values: Draft, Submitted, Approved, Rejected, Not Required. |
| Approved By | Enter the name or role approving the roadmap item or milestone; use N/A if approval is not required or not yet assigned. |
| Last Updated | Enter the date this row was last reviewed or amended in YYYY-MM-DD format. |

### Maintenance

The ISMS Manager owns this roadmap template, with updates at least monthly and after major scope, risk, resource, or milestone changes. Source data should be drawn from the ISMS project plan, risk register, statement of applicability, action tracker, ticketing/project management system, and management review decisions.
