### Column Guidance

| Column | What to enter |
|---|---|
| PCI DSS Requirement Reference | Enter the specific PCI DSS v4.0.1 requirement or sub-requirement this responsibility supports, using the official numbering format, e.g. 1.1.1, 3.5.1, 8.2.8, 12.4.1, or 'All X.1.2 requirements' where applicable. |
| Requirement Area | Enter the PCI DSS requirement area name or short description, e.g. 'Build and Maintain a Secure Network and Systems', 'Protect Account Data', 'Maintain an Information Security Policy'. |
| Control Activity / Responsibility | Enter the specific activity that must be performed to meet the PCI DSS requirement, stated as an action, e.g. 'Maintain network security control configuration standards' or 'Review user access privileges'. |
| Responsibility Description | Describe exactly what the assigned role is responsible for doing, including the expected outcome; do not enter generic statements such as 'responsible for PCI'. |
| RACI Designation | Enter one allowed value: Responsible, Accountable, Consulted, or Informed. Use separate rows where multiple RACI roles apply to the same PCI DSS activity. |
| Assigned Role / Function | Enter the job role, team, or function assigned to the responsibility, e.g. 'Network Security Team', 'CISO', 'IAM Administrator'; avoid relying only on a person's name. |
| Named Owner | Enter the current individual assigned to the role, using full name or corporate user ID, or enter 'TBD' only if not yet assigned. |
| Deputy / Backup Role | Enter the backup role or team that performs the responsibility when the primary owner is unavailable; use a role/function rather than only a name. |
| Accountable Executive | Enter the senior management role accountable for ensuring the responsibility is performed, e.g. 'CISO', 'CIO', 'Head of Technology', 'Compliance Director'. |
| Consulted Roles | Enter roles or teams that must provide input before or during the activity; separate multiple entries with semicolons. |
| Informed Roles | Enter roles or teams that must be notified of outputs, decisions, or completion; separate multiple entries with semicolons. |
| Frequency / Trigger | Enter how often or when the activity occurs, using values such as 'Daily', 'Weekly', 'Monthly', 'Quarterly', 'Annually', 'Upon change', 'Upon hire', 'Upon termination', 'Upon incident', or a specific defined trigger. |
| Applicable Environment / Scope | Enter the systems, processes, locations, business units, or PCI scope to which the responsibility applies, e.g. 'CDE', 'Connected-to systems', 'All in-scope service providers', 'Retail POS environment'. |
| Related Policy / Procedure Reference | Enter the document name, ID, or hyperlink for the policy, standard, procedure, or runbook that defines how the responsibility is performed. |
| Evidence / Output Produced | Enter the record or artifact generated to demonstrate the responsibility was performed, e.g. 'Access review sign-off', 'Firewall rule review record', 'Vulnerability scan report', 'Training completion report'. |
| Evidence Location / System of Record | Enter the repository, tool, ticketing system, GRC platform, document library, or log source where evidence is retained, including path or system name where applicable. |
| Understanding / Communication Method | Record how the assigned personnel are made aware of and understand their responsibilities, e.g. 'Role description', 'Policy attestation', 'PCI responsibility briefing', 'Training module', 'Team operating procedure'. |
| Assignment Approval | Enter the approver role/name and approval reference, e.g. 'CISO approval in GRC-12345' or 'Security Steering Committee minutes YYYY-MM-DD'. |
| Effective Date | Enter the date the responsibility assignment becomes effective in YYYY-MM-DD format. |
| Last Reviewed Date | Enter the date this responsibility assignment was last reviewed for accuracy in YYYY-MM-DD format. |
| Next Review Due Date | Enter the next scheduled review date in YYYY-MM-DD format, based on the organisation's review cadence. |
| Status | Enter one allowed value: Draft, Active, Pending Approval, Retired, or Superseded. |
| Notes / Exceptions | Enter any temporary exception, dependency, clarification, or transition note; if none, enter 'None'. |

### Maintenance

The PCI Compliance Manager owns this template, with accountable oversight from the CISO or designated executive responsible for PCI compliance. It is reviewed at least annually and whenever PCI scope, organisational roles, processes, or control ownership changes, using inputs from the GRC platform, HR role records, IAM system, policy library, service ownership register, and PCI DSS responsibility assignments.
