5. End to End Runtime Flow

Scanner ingestion to compliance evidence to risk treatment.

Diagram 5. Vulnerability ingestion to compliance and risk flow

Thick solid arrow: deterministic flow. Shaded box: async worker step. Every step also writes to the cross cutting Audit Log container.
Flow summary. Twelve steps from raw scanner output to executive notification. Each step is an isolated, audited operation. Steps 2 to 4 run in async workers. Steps 6 to 12 run through the workflow engine, so the entire chain is configurable per tenant without code changes.

9. Multi Tenancy and Security

Isolation model, encryption, audit, RBAC.
ConcernMechanism
Tenant isolationOne PostgreSQL database per tenant. Tenants table in master registry holds connection strings. Sessions opened per request after slug or header resolution.
Request authenticationJWT HS256 cookie, 24 hour TTL, 6 hour refresh threshold, MFA capable
Authorization140+ permissions on (resource, action). Roles compose permissions. Optional business unit scoping.
Password policyPer tenant configurable. Complexity, history, lockout, idle timeout.
SSOEntra ID, Google Workspace, SAML, OIDC, LDAP. SCIM 2.0 inbound provisioning.
Audit trailEvery CRUD writes AuditLog with actor, IP, before and after JSON diff. Indexed by (tenant_id, timestamp).
Secret storageIntegration credentials Fernet encrypted. Cloud connector credentials AES via CONNECTOR_MASTER_KEY. OAuth tokens encrypted separately.
Evidence filesFernet encrypted at rest per tenant. Object store layer abstracted.
Background tasksCelery args[0] always tenant slug. Validation in _payload_tenant before any DB access.
Cookie domainConfigurable via AUTH_COOKIE_DOMAIN env. Defaults to .localhost in dev.
