Context
We have implemented an AI-assisted compliance assessment engine in a GRC platform. Users upload evidences (policies, procedures, logs, screenshots, configurations, etc.) which are analyzed by AI to determine applicable compliance frameworks, controls, and clauses.

Problem Observed
When the same set of evidences is uploaded and the AI assessment is run multiple times, the following issues occur:

The recommended applicable frameworks and controls change on each run

Previously matched controls are sometimes removed or replaced

Evidence-to-control mappings are not stable or deterministic

The system does not clearly state:

Which exact framework

Which control ID

Which clause/sub-clause
the uploaded evidence satisfies

This creates audit risk, loss of confidence, and regulator non-acceptance.

🔍 Root Cause Analysis Required

Investigate and identify:

Whether the AI assessment is non-deterministic (e.g. temperature, randomness, embeddings re-generated each run)

Whether evidence embeddings are being recomputed instead of cached

Whether framework control definitions are normalized and fixed

Whether scoring thresholds or similarity cut-offs are dynamic

Whether multiple frameworks are being inferred without a primary framework anchor

Whether control-to-evidence matching is happening at:

Document level instead of clause level

Semantic similarity only without rule-based validation

✅ Required Functional Fixes

Implement the following mandatory corrections:

1️⃣ Deterministic AI Assessment

Ensure AI assessment produces the same output for the same evidences

Fix model parameters (temperature = 0, deterministic embeddings)

Cache embeddings for uploaded evidences

2️⃣ Clause-Level Evidence Mapping

For every uploaded evidence, the system must output:

Framework Name (e.g. ISO 27001:2022)

Control ID (e.g. A.5.1)

Clause / Sub-Clause (exact reference)

Control Title

Matching Rationale (why this evidence matches)

Confidence Score (%)

Evidence Coverage Type:

Full

Partial

Supporting

Not Applicable

⚠️ No control should be marked applicable without an explicit clause match

3️⃣ Stable Control Mapping Logic

Lock previously validated mappings unless:

Evidence is deleted

Framework version changes

User explicitly re-triggers reassessment

Do NOT reshuffle framework applicability on every run

4️⃣ Explainability & Audit Trail

Add an AI Explainability Panel that shows:

Text snippets from evidence used for matching

Exact control language matched

Similarity score used

Rule-based validation outcome

Timestamp of assessment

Model version used

5️⃣ Assessment Modes

Introduce assessment modes:

Initial Assessment

Incremental Re-Assessment (delta only)

Locked Audit Mode (read-only, no AI drift)

🎯 Expected Outcome

After implementing the above:

Running AI assessment multiple times with the same evidence:

MUST produce identical results

Every evidence must map to:

Exact framework

Exact control

Exact clause

Output must be auditor-defensible and regulator-ready

📌 Deliverables Required

Updated AI assessment logic (documented)

Stable evidence-to-control mapping engine

Clause-level mapping output schema

Explainability UI component

Unit tests proving deterministic behavior
